# خطة تشغيل Gate 0 — 2026-08-26

**الحالة:** `READY_FOR_EXECUTION / INCONCLUSIVE UNTIL HUMAN DATA`.
**المالك التشغيلي:** Product Owner يعيّن الأسماء المؤسسية أدناه قبل الإرسال.
**نطاق الخطة:** تجربة Wizard-of-Oz النصية وفق بروتوكول Gate 0؛ لا Pulse أو Unity أو LLM أو بيانات مرضى حقيقية.[1]

> هذه خطة جدولة وتشغيل، لا دليل تنفيذ. لا توجد أسماء مشاركين أو جلسات أو نتائج أو مراجعات خارجية مسجلة عند اعتمادها. لذلك لا يجوز إعلان `PASS` أو `PIVOT` أو قبول طبي استنادًا إلى هذه الوثيقة وحدها.

## 1. هدف التنفيذ وحدود القرار

الهدف هو اختبار ما إذا كانت العواقب المتغيرة والخط الزمني/إعادة المحاولة تضيف قيمة تعلمية واضحة تتجاوز الجدة، مقارنة بحالة تقليدية ثابتة. الحد الأدنى لاكتمال بوابة القرار هو **خمسة متعلمين سريريين حقيقيين على الأقل** و**ثلاثة أطباء أو مثقفين/مدرسين سريريين أو محاكاة على الأقل**.[1]

| القرار الممكن | متى يجوز إعلانه | ما لا يثبته |
|---|---|---|
| `PASS (directional)` | بعد استكمال العينة، التحقق من التزام النص، وتحليل البيانات وفق بروتوكول Gate 0. | فعالية تعليمية إحصائية أو جاهزية Unity أو صحة Pulse سريريًا. |
| `PIVOT / REWORK` | إذا تحقق أي STOP criterion موثق في البروتوكول. | أن الفريق أخفق في تنفيذ البرنامج أو أن simulation غير ممكنة تقنيًا. |
| `INCONCLUSIVE` | إذا لم تكتمل العينة أو كان الدليل غير صالح/ناقص عند تاريخ cutoff. | نجاحًا أو فشلًا. هذا هو القرار الحالي. |

## 2. الأدوار والمسؤوليات

| الدور المطلوب | مسؤولية لا تفوض آليًا | مخرج إلزامي |
|---|---|---|
| Product Owner | تعيين المؤسسة/جهة التواصل، قبول أو إيقاف الجدول، عدم التعويض بمشاركة وهمية. | تأكيد أسماء المالكين وقناة التوظيف. |
| Research Lead | التحقق من أن الاستكشاف مسموح محليًا أو إحالة الأمر إلى IRB/سياسة المؤسسة قبل التجنيد. | سجل قرار أخلاقي/مؤسسي مختصر. |
| Facilitator | تشغيل A وB بالنص المحايد نفسه، ضبط الوقت، وعدم الثناء على النسخة B. | ورقة evidence مجهولة لكل جلسة. |
| Scheduler / Recruitment Lead | الدعوات، فحص معايير الإدراج، توفير slot منفصل لكل مشارك. | ledger منفصل، لا يدخل المستودع. |
| Data Steward | فصل بيانات الاتصال عن رموز المشاركين، وإتاحة corpus منزوع الهوية للتحليل فقط. | مجلد restricted مؤسسي وmanifest بلا PII. |
| Secondary Reviewer (إن توفر) | ترميز عينة بلا معرفة ترتيب A/B لتقليل تحيز التأكيد. | ملاحظات codebook مستقلة. |
| Medical/Education Review Coordinator | إرسال الحزمة المستقلة وتسجيل الردود الخارجية؛ لا يوقع بالنيابة عن مراجع. | dispatch log وردود محفوظة وفق سياسة المؤسسة. |

إذا لم تكتمل العينة الصحيحة بحلول 2026-09-18، فالنتيجة التشغيلية هي `INCONCLUSIVE` وتتحول الخطة إلى **تجنيد جديد بموافقة Product Owner**، لا إلى PASS ولا إلى تمديد صامت.

## 4. التجنيد والجدولة والعشوائية

تستخدم الدعوة وصفًا محايدًا: تجربة استكشافية لحالتين تعليميتين قصيرتين في طب الصدمات، **وليست** اختبارًا لخبرة المشارك أو تدريبًا علاجيًا. لا يرسل الميسر مبرر المنتج أو تفضيل النسخة B قبل المقابلة. يلزم consent مناسب للمؤسسة قبل كل جلسة.[1]

| slot مجهول | المجموعة | الترتيب المحجوز | حالة التنفيذ المسموح تدوينها |
|---|---|---|---|
| L01، L03، L05 | متعلمون سريريون | A → B | `scheduled / completed / no-show / withdrawn` |
| L02، L04 | متعلمون سريريون | B → A | `scheduled / completed / no-show / withdrawn` |
| E01، E03 | أطباء/مثقفون | A → B | `scheduled / completed / no-show / withdrawn` |
| E02 | طبيب/مثقف | B → A | `scheduled / completed / no-show / withdrawn` |
| R01–R02 | احتياط متوازن | يعوضان الترتيب الناقص فقط | لا يدخلان التحليل ما لم يكملا الجلسة. |

المقصود هو توازن `A→B` و`B→A` عبر الحد الأدنى ذي الثمانية مشاركين. لا تحسب الأفعال أو سرعة الأفعال كدرجة سريرية؛ تسجل فقط لفهم ما الذي ناقشه المشارك.[1]

## 5. بروتوكول اليوم الواحد

كل جلسة فردية مدتها 35–50 دقيقة. يستخدم الميسر [`facilitator-script.md`](facilitator-script.md) و[`participant-information-and-consent-template.md`](participant-information-and-consent-template.md)، ويحفظ الالتقاط في قالب [`evidence-capture-sheet.csv`](evidence-capture-sheet.csv) تحت رمز مجهول.[2]

| المرحلة | الزمن | ضابط الجودة |
|---|---:|---|
| consent + تعريف | 3–5 دقائق | تأكيد أن المشاركة ليست تقييمًا وأن الانسحاب مسموح وفق السياسة. |
| تعويد محايد | دقيقتان | لا يكشف فرضية أن B "أفضل". |
| A أو B الأولى | 8–10 دقائق | نص موحد؛ تسجل العواقب/طلبات الأدلة لا صحة سريرية للأداء. |
| فاصل | دقيقتان | سؤال محايد أو استراحة. |
| النسخة المقابلة | 8–10 دقائق | لا تكشف التشخيص الخفي قبل الدليل المتاح. |
| خط زمني/إعادة محاولة B | 4–6 دقائق | لا يدعي أثر علاجي محسوب أو شفاء من الصدمة. |
| مقابلة | 8–12 دقائق | تحفظ الاقتباسات المؤيدة والمخالفة وسير العمل/الدقة. |

بعد كل يوم تشغيل، يفحص Data Steward أن كل record يحتوي الرمز والدور والترتيب والأسئلة الأساسية وملاحظة التزام النص، من دون اسم أو بريد أو رقم هاتف في corpus التحليل.

## 6. البيانات والتحليل والقرار

يفصل ledger التواصل المحمي مؤسسيًا عن مجلد الدراسة. يحتفظ المستودع بقوالب فقط؛ لا يرفع consent موقع أو تسجيل أو PII أو رد طبي باسم شخص. يراجع شخص ثانٍ، إذا أمكن، عينة من الملاحظات بلا معرفة ترتيب النسخة. التحليل وصفي/موضوعي لا اختبار إحصائي، ويستخدم [`codebook.md`](codebook.md) و[`decision-memo-template.md`](decision-memo-template.md).[1] [2]

| فحص 2026-09-23 | الدليل الأدنى | أثر القرار |
|---|---|---|
| اكتمال العينة | ≥5 learner records و≥3 educator records صالحة. | إن لم يتحقق: `INCONCLUSIVE`. |
| قيمة تتجاوز الجدة | موضوعات واقتباسات متعددة تصف أثرًا على التفكير/التفريغ. | غياب الأغلبية يدفع `PIVOT/REWORK`. |
| استعداد المدرسين | ≥2 من 3 educators مستعدين لتجربة محدودة بافتراض دقة محتوى مناسبة. | أقل من 2 يدفع `PIVOT/REWORK`. |
| محرك التبني وسير العمل | لا يوجد عائق workflow/content مسيطر غير معالج. | وجوده يدفع `PIVOT/REWORK`. |
| سلامة التفسير | يذكر memo أن Gate 0 لا يثبت فعالية أو صحة طبية أو readiness Unity. | غيابها يمنع النشر/القرار. |

## 7. مراجعة طبية/تعليمية مستقلة: dispatch checklist

المراجعة الطبية ليست جزءًا من عينة Gate 0 ولا يمكن للميسر أو Product Owner توقيعها بالنيابة. تبقى حالتها `READY_FOR_REVIEW / UNVALIDATED` إلى أن يصل رد خارجي موثق.[3]

| خطوة | موعد مستهدف | artifact | حالة اليوم |
|---|---|---|---|
| تحديد مراجع مستقل/اختصاص وخبرته | 2026-08-27–2026-08-31 | reviewer roster محفوظ مؤسسيًا | `NOT STARTED` |
| تجميد bundle/version list | 2026-09-01 | links إلى السيناريو والعقود والمصفوفة وبروتوكول Gate 0 | `NOT STARTED` |
| إرسال طلب المراجعة وحدوده | 2026-09-01 | dispatch log + deadline 2026-09-15 | `NOT STARTED` |
| متابعة واحدة غير ضاغطة | 2026-09-10 | follow-up log | `NOT STARTED` |
| استلام ACCEPT/REWORK/OUT_OF_SCOPE موقّع/مُقَر وفق المؤسسة | حتى 2026-09-15 | packet completion record | `NOT STARTED` |
| فهرسة التعديلات وقرار Product Owner | 2026-09-16–2026-09-18 | redacted review summary | `NOT STARTED` |

**الحالة النهائية الآن:** لا يوجد participant evidence ولا review response. لذلك تظل Gate 0 `INCONCLUSIVE` وتظل المراجعة `UNVALIDATED`، ويظل Unity محجوبًا حتى يكتمل الاثنان ويقرر Product Owner الخطوة التالية.
