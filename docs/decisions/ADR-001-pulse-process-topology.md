# ADR-001: فصل VPE Runtime وجعل Pulse ذا مالك واحد

- **الحالة:** Accepted for S0 headless foundation.
- **التاريخ:** 2026-08-22.
- **القرار مرتبط بـ:** [Gate A](../reports/002-pulse-gate-a.md) و[`DEC-007` إلى `DEC-011`](../../../projects/noxora-test-5f6dec15/nexora_vpe_decisions_DEC-007_to_DEC-011.md).

## السياق

أثبتت Gate A تشغيل Pulse headlessly، وتقدم الزمن، والنزف الداخلي الطحالي، وإيقاف النزف، ومركبي Saline وPackedRBC، وحفظ/استعادة حالة. كما أظهرت تجربة الاستعادة أن برنامج تشغيل Pulse يطبع تشخيصًا يعتمد زمنًا نسبيًا رغم استمرار الحالة فعليًا على الزمن المطلق. يحتاج S0 لذلك إلى طبقة تملك ترتيب الأوامر والزمن والأدلة واللقطات، بدل وصول Unity أو طبقة لغة إلى Pulse مباشرة.

## القرار

يكون **VPE Runtime منفصلًا ومن دون واجهة Unity داخلية** هو المالك الوحيد لترتيب الوصول إلى Pulse. ينفذ هذا المستودع العقد headless بلغة Python، ويعبر إلى Pulse عبر `PulseAdapter` مثبت الإصدار الذي يشغّل عملية C++ محلية واحدة تملك مثيل SDK واحدًا. لا يصل العميل المستقبلي، ولا LLM، ولا أي عملية أخرى إلى Pulse مباشرة.

```text
Future Client / Unity / Optional Language UX
                 ↓ structured command
          VPE Runtime (single owner)
                 ↓ narrow physiology adapter
          Pinned Pulse installation
                 ↓
       telemetry + state snapshots
                 ↓
          evidence / replay store
```

## البدائل التي قورنت

| البديل | النتيجة | السبب |
|---|---|---|
| Pulse داخل Unity/C# مباشرة | مرفوض حاليًا | يضعف العزل والاختبار headless ويمنح العميل ملكية ضمنية للزمن. |
| VPE headless منفصل + adapter | **مختار** | يتسق مع Gate A، ويعزل الأعطال، ويجعل الاختبارات وإعادة التشغيل وعميلًا مستقبليًا ممكنة. |
| إعادة بناء محرك فسيولوجيا مخصص | مرفوض | لا يحقق هدف إعادة استخدام Pulse ويزيد نطاق S0 بلا دليل حاجة. |

## العواقب

يحتفظ runtime بطابور أوامر مرتب، وساعة محاكاة مستقلة، ومخزن أحداث/لقطات. تحمل كل لقطة نسخة محرك/adapter معلنة. تحقق التنفيذ الحالي من adapter حقيقي عبر local stdio محدود بين Python وخادم C++، وتتحقق اختبارات التكامل من الزمن والتدخلات واللقطات والاستعادة. يبقى نموذج نشر خدمة بعيدة أو إدارة عمليات متعددة قرارًا لاحقًا خارج S0.

## حواجز القبول

1. لا يمر أمر إلى adapter قبل تحقق عقد السيناريو وقاموس التدخلات.
2. لا يقبل S0 سوى وضع `learning` ولا ينشئ نجاحًا/فشلًا عالي العواقب.
3. يختبر adapter الحقيقي صراحةً الزمن المطلق بعد الاستعادة، ولا يعتمد على رسالة `PulseScenarioDriver` وحدها.
4. يظل كل تشغيل قابلًا للنسبة إلى revision Pulse وحالة/سيناريو ومدخلات مرتبة.
5. ينفذ `PulseAdapter` التحقق من hash SDK وقاموس التدخلات وdigest ملف الحالة قبل الاستعادة؛ انظر [عقد العملية](../contracts/pulse-adapter-process-contract.md) و[تقرير التكامل](../reports/004-pulse-adapter-integration.md).

## ما لا يقرره ADR

لا يثبت ADR ملاءمة سريرية، ولا يختار Unity، ولا يفعّل LLM، ولا يضيف FAST ثلاثي الأبعاد، ولا يفرض نموذج نشر بعيد أو إدارة عمليات متعددة.
