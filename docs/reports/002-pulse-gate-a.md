# تقرير بوابة Pulse A — دليل تشغيل محلي قابل للتحقق

> **الحالة:** اجتياز هندسي مشروط. يثبت هذا التقرير أن تكاملًا محدد الإصدار من Pulse يمكنه تنفيذ سيناريوهات النزف، وإيقاف النزف، وإعطاء مركبي Saline وPackedRBC، وإنتاج تيليمترية CSV، وحفظ/استعادة حالة تشغيلية بصورة متسقة. لا يثبت التقرير صحة سريرية أو صلاحية للاستخدام في قرار علاجي.

## 1. الهدف وحدود الادعاء

تختبر **بوابة A** قابلية تشغيل محرك [Pulse Physiology Engine][1] ضمن نطاق S0 فقط. ينحصر السؤال في: هل يمكن لسير عمل قابل لإعادة الإنتاج تشغيل حالة مرجعية، تطبيق تدخلات فعلية يعلن Pulse دعمها، تسجيل مخرجات رقمية، واستعادة حالة محفوظة دون فقدان الاستمرارية؟

لا تستخدم النتائج كاقتراح جرعات، أو بروتوكول علاج، أو نظام إنذار، أو تقييم مريض. تعد قيم السيناريو **مدخلات اختبارية للمحاكاة** وليست توصيات طبية.

| بند البوابة | النتيجة | الدليل |
|---|---|---|
| بناء Pulse headless محليًا | ناجح | تثبيت `PulseScenarioDriver` وواجهات C++/Java/Python |
| إنشاء حالة مرجعية | ناجح | `gendata` ثم `genStates` أنشآ `StandardMale@0s.json` |
| نزف داخلي طحالي قابل للتحكم | ناجح | CSV وملخص `internal_spleen_observability.csv` |
| إيقاف النزف | ناجح | يصبح معدل النزف الكلي `0` في الصف التالي لإجراء الإيقاف |
| إعطاء Saline | ناجح | سجل التنفيذ يثبت الإجراء واكتمال التسريب؛ CSV محفوظ |
| إعطاء PackedRBC | ناجح | سجل التنفيذ يثبت الإجراء؛ CSV محفوظ |
| حفظ/استعادة حالة | ناجح مع ملاحظة تشخيصية | تطابق رقمي تام في 121 صفًا متداخلًا بعد الاستعادة |
| صلاحية سريرية أو قرارية | **غير مثبتة وخارج النطاق** | لا توجد معايرة أو تحقق سريري أو مراجعة سريرية ضمن هذه البوابة |

## 2. منشأ البناء والتكرارية

استُخدم فرع `stable` الذي تصفه وثائق Pulse بأنه الفرع الموصى به للتطبيقات والدراسات، وليس فرع `integration` غير المتحقق يدويًا [2]. جرى بناء المصدر محليًا دون تعديل محتوى المصدر.

| عنصر | القيمة المثبتة |
|---|---|
| Pulse source revision | `e8a36497b8ba78e788dc201a6baf74e1c297c56f` |
| إصدار ظاهر في الحالة المحفوظة | `4.3.2` |
| نمط البناء | `Release` |
| واجهة Java | مفعلة |
| واجهة Python | مفعلة |
| تنزيل baselines | معطل؛ ليس لازمًا لسيناريوهات البوابة |
| CMake | `3.28.3` |
| GCC | `13.3.0` |
| OpenJDK | `21.0.11` |
| Python | `3.12.3` |

اتّبع التنفيذ تسلسل Pulse المعلن: بناء المحرك، ثم `./run.sh gendata` لإعداد بيانات المحرك، ثم `./run.sh genStates` لتوليد حالات البداية [3]. الحالة المرجعية الناتجة هي `StandardMale@0s.json`، ولا تُضمّن في المستودع لأنها ناتج محرك كبير يمكن إعادة توليده من المصدر المثبت.

## 3. تصميم التجارب

التجارب قابلة للتشغيل من مجلد تثبيت Pulse `install/bin` بعد إعداد البيانات والحالات. تحفظ تعريفاتها في [`experiments/pulse_gate_a/scenarios/`](../../experiments/pulse_gate_a/scenarios/)؛ ويحفظ ناتجها الخام في [`experiments/pulse_gate_a/results/2026-08-22/`](../../experiments/pulse_gate_a/results/2026-08-22/).

| التجربة | التدخلات | زمن المحاكاة | ما تثبته |
|---|---|---:|---|
| `internal_spleen_observability` | نزف داخلي في الطحال عند `60 mL/min`؛ ثم إيقافه | 1660 s | فعل نزف داخلي، مخرج معدل/حجم النزف، الإيقاف، والمخرجات الفسيولوجية |
| `hemorrhage_saline_observability` | نزف مزدوج، إيقاف، ثم Saline بكمية `500 mL` ومعدل `100 mL/min` | 1140 s | تنفيذ مركب Saline بعد النزف وتسجيل أثر المحرك |
| `hemorrhage_packed_rbc_observability` | نزف مزدوج، إيقاف، ثم PackedRBC بكمية `250 mL` ومعدل `5 mL/min` | 2880 s | تنفيذ مركب PackedRBC بعد النزف وتسجيل أثر المحرك |
| `snapshot_seed_*` + `snapshot_restore_*` | حفظ لقطة عند `150 s` خلال نزف طحالي نشط؛ استعادة ثم تقدم `120 s` | 270 s | استمرار حالة ومحرك نشط عبر الحفظ/الاستعادة |

اعتمدت أشكال الأفعال والمركبات على سيناريوهات Pulse الرسمية المتاحة في نسخة المصدر، بما فيها نزف طحالي داخلي ومركبا `Saline` و`PackedRBC`. تعرض وثائق المحرك أن النظام مصمم للمحاكاة الفيزيولوجية وبيانات التدريب والبحث، لا كبديل للتحقق السريري [1].

## 4. الأدلة الرقمية

### 4.3 استمرارية الحفظ والاستعادة

حُفظت لقطة محرك عند `150 s` أثناء نزف طحالي مستمر ثم حمّلها سيناريو ثانٍ. قارَن التحليل صفوف CSV المتداخلة من `150 s` إلى `270 s` عبر خمس متغيرات: معدل النزف، حجم النزف، معدل القلب، MAP، وحجم الدم.

| صفوف متداخلة مقارنة | بداية التداخل | نهاية التداخل | أكبر فرق عددي مطلق | النتيجة |
|---:|---:|---:|---:|---|
| 121 | 150 s | 270 s | 0.0000 | تطابق رقمي تام |

> **ملاحظة تشخيصية:** يعرض `PulseScenarioDriver` رسالة خطأ في نهاية سيناريو الاستعادة لأنه يقارن الزمن المطلق النهائية (`270 s`) بزمن التقدم المطلوب (`120 s`). رغم هذه الرسالة، حمل المحرك الحالة عند `150 s`، تقدم إلى `270 s`، وتطابقت كل الصفوف المتداخلة رقميًا. يجب أن يعالج غلاف Nexora فرق الزمن المطلق/النسبي صراحةً، وألا يعتمد على رسالة السائق وحدها كمعيار نجاح.

## 5. القرار الهندسي

يمكن للنواة المحدودة في S0 أن تستخدم Pulse عبر **عقد محرك ضيق** يحتوي على: حالة بداية مرجعية، فعل نزف محدد، فئة إجراء سائل/مركب مدعومة، زمن محاكاة، ومجموعة تيليمترية مُسوّرة. لا يجوز للمراحل الأولى عرض أي مخرجات على أنها توصيات، أو بناء منطق بروتوكولي مفتوح، أو إخفاء إصدار المحرك والحالة المستخدمة.

| قرار | الوضع | أثر التنفيذ |
|---|---|---|
| تثبيت Pulse revision | معتمد لـ S0 | يسجل الإصدار في كل تشغيل وmanifest للأدلة |
| استخدام حالة بدء مرجعية | معتمد لـ S0 | إعادة توليد موثقة؛ لا يُخزّن ناتج الحالة الثنائي/الكبير في المصدر |
| تثبيت قاموس الأفعال والمركبات | معتمد لـ S0 | يقتصر النموذج الأولي على أسماء/وحدات معتمدة ومُتحقق منها |
| الاستمرارية عبر snapshot | معتمدة مع غلاف تحقق | يتحقق الغلاف من الزمن المطلق وملفات CSV، لا من كود خروج السائق فقط |
| توافق BLA أو طبقة المعرفة | غير منفذ | يبقى بوابة مستقلة قبل أي تكامل دلالي |
| صلاحية سريرية | غير مثبتة | تتطلب مسار تحقق وحوكمة منفصلين ومراجعة مختصين |

## 6. خطوات التكرار

1. استنسخ Pulse عند `e8a36497b8ba78e788dc201a6baf74e1c297c56f` وابنه بوضع `Release` مع Java وPython.
2. من `install/bin` شغّل `./run.sh gendata` ثم `./run.sh genStates` وفق توثيق Pulse [3].
3. نفذ `PulseScenarioDriver` لكل ملف في `experiments/pulse_gate_a/scenarios/` من نفس مجلد `install/bin`، لأن تعريفات السيناريو تستخدم مسارات نتائج نسبية.
4. انسخ ملفات CSV إلى `results/<date>/` وشغّل `python3 experiments/pulse_gate_a/scripts/summarize_gate_a.py`.
5. تحقق من ملفات CSV عبر `sha256sum --check SHA256SUMS.txt`.
